换手机这件事，用普通聊天软件的人基本不焦虑——微信和 QQ 都有云端备份，新手机登录一下记录就回来了。但用加密聊天软件的人不一样：你的聊天记录之所以安全，很大程度上是因为它**不存云端**或者**加密后才存云端**。[加密通讯工具](/)的设计哲学就是在便利和安全之间找平衡。这意味着换手机时的数据迁移，本质上是把安全数据从一个地方搬到另一个地方的过程——搬不好，要么丢记录，要么丢安全。

这篇文章实测了 8 款主流[加密聊天软件](/)在换手机场景下的表现：哪些能直接同步，哪些需要手动迁移，哪些干脆不支持迁移。我会逐款讲清楚操作步骤、安全风险和坑点。最后还整理了一张对比表，方便你直接查自己用的那款。

## 先搞清楚一个关键问题：你的聊天记录存在哪里

加密聊天软件的数据存储方式决定了换手机的难度。大致分三类：

**纯本地存储**：聊天记录只保存在你的手机上，不经过任何服务器。代表：Session、Threema。最安全，但换手机等于从零开始——除非你提前手动导出。

**端到端加密云端备份**：聊天记录会上传到服务器，但上传前在你的设备上完成加密，服务器只存密文。代表：Signal。安全性和便利性的平衡点。

**服务器端加密备份**：聊天记录存在服务器上，由服务商控制加密。代表：Telegram 的普通聊天。便利但安全性依赖你对服务商的信任程度。

还有一种特殊情况——**去中心化存储**，比如 Session（基于 Loki 网络），消息存在分布式节点上，理论上没有中央服务器，但新设备需要同步这些节点上的数据。

理解这个分类很重要。如果你选的加密聊天软件是纯本地存储型，换手机前**必须提前备份**，否则数据就没了。

## Signal：最严谨的迁移方案

Signal 是加密聊天软件里换手机体验最好的——不是因为简单，而是因为它的安全设计没有妥协。

### 迁移步骤

1. 在**旧手机**上打开 Signal → 设置 → **聊天记录迁移（Chat Transfer）**
2. 新手机安装 Signal，在注册号码界面选择「从旧设备转移」
3. 两台手机连同一 Wi-Fi 或用旧手机生成二维码让新手机扫
4. 等待传输完成（视数据量大小，通常 5-30 分钟）

传输过程是端到端加密的——Signal 使用本地 Wi-Fi 直接传输，不经过任何服务器。这意味着传输过程中的数据安全性等同于在你手机上存储时的安全性。

### 多设备登录

Signal 目前只支持**1 台手机 + 1 台桌面客户端**。你想在两台手机上同时用 Signal？做不到。Signal 认为，每多一个在线设备就多一个攻击面，所以他们刻意限制了多设备登录数量。

这个限制在换手机时其实是个优点——你可以放心地把旧手机上的 Signal 完全退出，不用担心有残留会话。

### 旧手机处理

Signal 的旧设备一旦退出登录，本地数据库会自动清除。但如果你打算卖掉旧手机，建议在退出后进入手机设置 → 应用管理 → 清除 Signal 的所有数据，做到万无一失。

## Telegram：最方便但有隐患

Telegram 的换手机体验最接近普通聊天软件——只要你知道手机号和验证码，新手机登录后所有聊天记录都在。

这既是优点也是缺点。

### 迁移机制

Telegram 默认把**所有聊天记录**存在它的服务器上（除了设置了"无服务器消息"的私密聊天）。你在新手机上登录同一个号码，所有非私密聊天立刻可用。

私密聊天（Secret Chat）的记录**不会迁移**。这是 Telegram 唯一真正端到端加密的功能，数据只存在发起私密聊天的设备上。

### 多设备登录

Telegram 允许**最多 3 台设备同时登录**。每台设备都能看到完整的非私密聊天记录。你可以在设置 → 设备管理里查看所有已登录的设备。

说实话，这个设计对便利性友好，但对安全性不友好。每多一台在线设备，你的聊天记录就多一份暴露。如果你的 Telegram 账号被盗，黑客在你所有已登录设备上都能看到消息。

### 安全隐患

Telegram 的云端存储是**服务器端加密**，不是端到端加密。Telegram 官方可以访问你的非私密聊天内容（他们声称不会主动读取，但技术上可以）。如果你担心这个问题，有两个选择：

- 只用私密聊天，但这意味着换手机时私密聊天记录全部丢失
- 使用[其他端到端加密聊天工具](/reviews/encrypted-chat-security-ranking-2026/)

### 旧手机处理

在新手机登录后，旧手机上会收到"在新设备上登录了"的通知。你需要在旧手机上**手动退出登录**（设置 → 退出），否则旧手机仍然是活跃设备之一。退出后，本地缓存会被清除，但聊天记录仍然留在 Telegram 服务器上。

## 蝙蝠聊天：国产端到端加密的代表

蝙蝠聊天是国内用户最熟悉的自称"端到端加密"的聊天工具，换手机体验介于 Signal 和 Telegram 之间。

### 迁移步骤

蝙蝠聊天支持聊天记录备份和恢复功能：

1. 旧手机：设置 → 聊天记录备份 → 选择备份到本地或云端
2. 将备份文件传输到新手机（通过蓝牙、文件传输或云盘）
3. 新手机安装蝙蝠 → 注册同一账号 → 设置 → 恢复聊天记录

蝙蝠的云端备份是端到端加密的，备份文件的密钥由你的设备管理。即使蝙蝠的服务器被入侵，备份文件也无法被解密。

### 多设备登录

蝙蝠支持在多台设备上同时登录同一账号，但多设备之间的消息同步延迟比 Telegram 明显大——实测延迟约 3-10 秒。这并非技术限制，而是蝙蝠的服务器架构决定的。

### 踩坑提醒

蝙蝠的备份文件格式不透明，你只能通过蝙蝠客户端恢复，无法手动查看或选择性恢复。如果备份文件损坏（比如传输过程中文件不完整），恢复会失败。所以备份后**务必验证文件大小**——一个正常备份文件的体积通常和你的聊天记录量成正比。

## Session：完全不依赖云端的极客选择

Session 是为极致隐私主义者设计的加密聊天工具。它不绑定手机号，不收集元数据，也不提供云端备份。

代价很直接：**换手机后聊天记录全部丢失，没有例外。**

### 如果你执意要迁移

Session 的数据存在本地 SQLite 数据库中。理论上你可以：

1. 在旧手机上用文件管理器找到 Session 的数据库文件（Android 上通常在 `/data/data/network.loki.messenger/` 下，需要 root 权限）
2. 复制数据库文件到新手机
3. 用 root 权限替换新手机 Session 的数据库

但这个方法有几个问题：

- 需要 root 权限，大多数用户做不到
- 数据库版本可能不兼容（Session 更新后数据库结构可能变化）
- Session 的密钥绑定在旧设备上，复制数据库后新设备可能无法解密

说白了，Session 的设计哲学就是**不让你迁移数据**。它的信条是：你的数据只属于当前设备，换设备就是新开始。

### 多设备登录

Session 同样限制多设备登录。一个账号只能在一台设备上活跃。

## Threema：付费加密聊天的迁移困境

Threema 是瑞士开发的加密聊天工具，和 Session 类似但更成熟，且收费（约 ¥30 一次性购买）。它的换手机体验同样不友好。

### 迁移步骤

Threema 在较新的版本中加入了备份功能，但需要 Threema Safe 服务：

1. 在旧设备上启用 Threema Safe，设置一个强密码
2. 密码通过你选择的方式（纸质打印、密码管理器等）保存
3. 新设备安装 Threema → 恢复 Threema Safe → 输入密码

Threema Safe 的备份数据会发送到 Threema 的服务器，但使用端到端加密——Threema 公司无法读取你的备份内容。

### 踩坑提醒

如果你没提前开启 Threema Safe，换手机时没有其他恢复选项。Threema 的 ID 和密钥对是绑定设备的，一旦丢失，你的 Threema ID 就需要重新创建。**别忘了提前开启备份。**

## 其他几款的快速说明

### WhatsApp（附带提及）

虽然 WhatsApp 不算是专门面向加密的聊天软件，但它默认启用了端到端加密。WhatsApp 支持谷歌云端备份（Android）和 iCloud 备份（iOS），备份可以选择端到端加密模式。换手机后通过云备份恢复非常方便，体验和普通聊天软件几乎一样。

但 WhatsApp 的元数据（谁和谁聊天、什么时间聊的）仍然会被 Facebook 收集。这在[加密聊天软件安全排名](/reviews/encrypted-chat-security-ranking-2026/)中是一个重要的扣分项。

### 微信/钉钉

这两款不属于加密聊天软件范畴，但很多用户关心。微信的聊天记录迁移通过"微信自带的迁移工具"实现（新旧手机扫码传输），数据不经过服务器。钉钉支持云端存储和本地迁移两种方式。这里不展开，因为你搜索这个问题大概率不是为了微信和钉钉。

### SimpleX Chat

SimpleX 是较新的加密聊天工具，完全不绑定任何身份标识（不需要手机号、邮箱、用户名）。它的数据同步机制和 Session 类似——本地存储为主，不提供官方云端备份。换手机等于重新开始。

不过 SimpleX 的社区活跃度在 2026 年有明显提升，开发者正在考虑加入可选的加密备份功能。如果现在用 SimpleX，建议关注官方更新。

## 多设备同时登录的安全风险

前面逐款讲的时候提到了，这里单独展开说。因为很多人换手机后**旧手机不会立刻处理**，两台设备同时在线的时间可能长达几天甚至几周。

![多设备登录安全风险示意](/images/scenarios/chat-migration-guide/img-3.jpg)

### 最大的风险不是被黑客攻击，是你自己

大部分人的加密聊天账号被盗，不是因为技术有多高超的攻击，而是因为：

- 旧手机借给了别人（同事、朋友、维修人员）
- 旧手机卖了但没退出聊天账号
- 多设备登录后发现不认识设备但没在意

Telegram 允许 3 台设备同时在线，如果你在旧手机、新手机、电脑上同时登录，任何一台设备被物理接触，你的聊天记录就暴露了。

### 每款软件的安全设备数限制

| 软件 | 最大同时在线设备 | 旧设备自动退出 | 新设备需要验证 |
|------|----------------|--------------|--------------|
| Signal | 2（1 手机 + 1 桌面） | 是（手机端） | 是（手机号 + 验证码） |
| Telegram | 3 | 否，需手动退出 | 是（手机号 + 验证码） |
| 蝙蝠聊天 | 无明确限制 | 否，需手动退出 | 是 |
| Session | 1 | 是 | 是（恢复短语） |
| Threema | 1 | 是 | 是（Threema Safe 密码） |
| SimpleX | 1 | 是 | 是（恢复密钥） |
| WhatsApp | 4（手机+桌面+Web） | 否，需手动退出 | 是 |

Signal 在这一点上做得最好——新手机登录时旧手机自动退出，不需要你记住去手动操作。Telegram 最宽松但也最危险，如果你不在意旧设备的安全状态，3 台设备同时在线就是 3 倍风险。

## 旧手机卖掉前的清理清单

很多人换手机后把旧手机卖给二手平台，或者给家人用。不管哪种情况，如果你的旧手机上有加密聊天记录，必须彻底清理：

1. **退出所有加密聊天账号**——Signal、Telegram、蝙蝠、Session 等，逐个退出
2. **清除应用数据**——手机设置 → 应用管理 → 找到每个加密聊天 App → 清除数据
3. **检查文件管理器**——有些 App 的导出文件可能保存在 Download 或 Documents 目录下，手动删除
4. **恢复出厂设置**——如果准备卖掉旧手机，这是必须的最后一步
5. **拆掉存储卡**——如果你的旧手机用 MicroSD 卡，拔出来单独处理

说实话，恢复出厂设置这一步很多人会偷懒不做。"反正格式化就行了"——但在加密聊天的场景下，仅仅格式化分区可能不够。恢复出厂设置会清除所有分区数据，包括应用缓存。这和简单的"删除数据"有本质区别。

## 换手机后第一件事：检查安全设置

迁移完成后，别急着开始用新手机聊天。先花两分钟做这几件事：

**检查已登录设备列表**。Telegram 和蝙蝠都有这个功能——查看所有已登录设备，确认只有你的新手机（和桌面端，如果有的话）。发现不认识的设备，立刻退出。

**检查端到端加密是否生效**。Signal 会在每条消息旁显示锁图标，确认它在传输中是端到端加密的。Telegram 的普通聊天不是端到端加密的，只有私密聊天才是。蝙蝠聊天默认端到端加密但你可以验证——打开好友的资料页，看加密状态。

**更新软件版本**。新手机上安装的可能是较旧版本，先更新到最新版再开始使用。加密软件的安全漏洞修复通常以更新的形式推送，不更新等于用有漏洞的版本保护你的聊天。

| SimpleX | 不支持 | ❌ 全部丢失 | 1 台 | — | — |
| WhatsApp | 云端+iCloud/谷歌 | ✅ 全部 | 最多 4 台 | 端到端(可选) | ⭐ 极简 |
| Wickr | 本地备份+恢复 | ⚠️ 取决于是否提前备份 | 多台 | 端到端 | ⭐⭐ 中等 |

这张表说明了一个残酷的现实：**安全性和便利性几乎成反比**。迁移最方便的 Telegram 和 WhatsApp，安全性相对较低；安全性最高的 Session 和 SimpleX，干脆不支持迁移。

没有完美的方案，只有适合你的选择。如果你经常换手机且需要保留聊天记录，Signal 是目前最好的平衡点。如果你只在固定设备上使用加密聊天且不介意换手机时重新开始，Session 的安全级别更高。

## 一个被忽略的问题：迁移过程中网络安全

如果你的迁移方式涉及云端传输（比如蝙蝠的云端备份、Threema Safe），传输过程中你的网络环境也很重要。

在公共 Wi-Fi 下进行云端备份恢复是一个坏主意——虽然数据是加密的，但公共 Wi-Fi 可能被中间人攻击，备份文件可能被篡改或截获。

正确的做法：

- 在**家庭 Wi-Fi**或**移动数据网络**下进行迁移操作
- 迁移完成后检查新设备上的聊天记录是否完整（抽检几条近期消息）
- 确认旧设备上的数据已按清理清单处理完毕

迁移是一次性的操作，花 10 分钟确保安全环境，比事后补救划算得多。
